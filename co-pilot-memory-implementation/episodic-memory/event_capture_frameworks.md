# Episodic Memory Event Capture Frameworks

## Event Classification System

### Event Significance Levels

**Level 1: Critical Episodes** (Always capture)
- Major architectural decisions
- Technology selection decisions
- Project milestone achievements/failures
- Significant incidents or outages
- Team composition changes
- Client/stakeholder feedback sessions

**Level 2: Important Episodes** (Capture when relevant)
- Feature completion milestones
- Code review discussions with significant learnings
- Performance optimization successes/failures
- Cross-team collaboration sessions
- Process improvements or changes
- Debugging sessions for complex issues

**Level 3: Notable Episodes** (Capture when time permits)
- Daily standup decisions
- Pair programming sessions with insights
- Small feature decisions
- Tool adoption experiences
- Learning moments or skill development
- Team social interactions affecting work

### Event Type Categories

**Decision Episodes**:
- Technical architecture choices
- Technology selection
- Process and workflow decisions
- Resource allocation decisions
- Timeline and priority decisions

**Interaction Episodes**:
- Team meetings and discussions
- Client/stakeholder communications
- Cross-team collaborations
- Mentoring sessions
- Conflict resolution conversations

**Achievement Episodes**:
- Project milestones reached
- Feature completions
- Performance improvements
- Bug resolution successes
- Learning goals achieved

**Challenge Episodes**:
- Problems encountered and resolved
- Failures and lessons learned
- Conflicts and their resolution
- Unexpected obstacles
- Resource constraints managed

## Rapid Capture Methods

### Quick Episode Templates

**5-Minute Decision Capture**:
```
What: [Brief decision description]
When: [Date/time]
Who: [Key people involved]
Why: [Context that prompted decision]
Choice: [What was decided]
Impact: [How this affects current work]
```

**2-Minute Meeting Capture**:
```
Meeting: [Brief description]
When: [Date/time]
Who: [Attendees]
Key Points: [Top 3 important items]
Decisions: [What was decided]
Actions: [Who does what]
```

**3-Minute Problem Resolution**:
```
Problem: [What went wrong]
When: [When it occurred]
Impact: [What was affected]
Solution: [How it was fixed]
Prevention: [How to avoid next time]
Learning: [Key insight gained]
```

### Context Capture Triggers

**Automatic Triggers** (Events that should always prompt capture):
- Project milestone dates
- Release deployments
- Incident escalations
- Team meeting conclusions
- Major decision announcements

**Manual Triggers** (Situations to recognize and capture):
- "That was an important conversation"
- "We should remember this decision"
- "This was a breakthrough moment"
- "That was more difficult than expected"
- "This approach worked really well"

### Progressive Detail Capture

**Immediate Capture** (During or right after event):
- Basic facts: who, what, when, where
- Key decisions or outcomes
- Primary emotional tone
- Immediate next actions

**Same-Day Enhancement** (Within 24 hours):
- Additional context and background
- Rationale for decisions made
- Alternative options considered
- Relationship to other projects/decisions

**Weekly Review Enhancement** (During weekly review):
- Long-term implications
- Patterns and connections to other episodes
- Lessons learned analysis
- Updates based on subsequent developments

## Selective Capture Guidelines

### High-Value Episode Indicators
Prioritize capturing episodes that:
- Involve multiple stakeholders with different perspectives
- Result in significant changes to direction or approach
- Reveal new information about team dynamics or capabilities
- Demonstrate successful or failed patterns
- Have potential impact on future decisions

### Low-Value Episode Indicators
Minimize time spent on episodes that:
- Are routine and follow established patterns
- Involve only individual work without broader context
- Have minimal impact on current or future projects
- Repeat patterns already well-documented
- Lack clear learning or decision value

### Context Sensitivity Assessment
```
Capture More Detail When:
- High uncertainty about outcomes
- Multiple valid options with trade-offs
- Significant stakeholder disagreement
- First-time or experimental approaches
- High-risk or high-impact situations

Capture Less Detail When:
- Following established patterns
- Low-risk routine decisions
- Clear consensus among stakeholders
- Well-understood problem domains
- Time-sensitive situations requiring quick action
```

## Episode Maintenance and Evolution

### Episode Lifecycle Management
```
Active Episodes (Recent and relevant):
- Recently captured (last 3 months)
- Currently referenced for decisions
- Active projects and ongoing situations
- Unresolved issues or pending outcomes

Archive Episodes (Historical but accessible):
- Completed projects and resolved issues
- Successful patterns worth preserving
- Important organizational history
- Significant learning experiences

Expired Episodes (Candidates for removal):
- Outdated technology or process information
- People who are no longer involved
- Situations unlikely to recur
- Lessons that have been thoroughly internalized
```

### Episode Update Protocols
```
Regular Updates:
- Add outcome information when results become clear
- Update relationship links as connections become apparent
- Enhance context as additional perspective becomes available
- Correct factual errors or incomplete information

Triggered Updates:
- When referenced episodes become relevant again
- When patterns emerge connecting multiple episodes
- When long-term outcomes validate or contradict initial assessments
- When similar situations arise requiring comparison
```
