# Problem-Solving Frameworks for Working Memory

## Framework Selection Guide

### Simple Problems (Single file/function)
**Use**: Linear Problem-Solving Framework
- Quick hypothesis-test cycles
- Minimal decomposition needed
- Direct solution approaches

### Complex Problems (Multi-component)
**Use**: Divide-and-Conquer Framework
- Systematic decomposition
- Dependency management
- Parallel workstream coordination

### Debugging Problems
**Use**: Scientific Investigation Framework
- Hypothesis-driven testing
- Evidence collection
- Systematic elimination

### Architecture Problems
**Use**: Design Space Exploration Framework
- Option generation and evaluation
- Constraint satisfaction
- Trade-off analysis

## Core Problem-Solving Patterns

### 1. Linear Problem-Solving Framework
```
Problem Definition → Analysis → Solution Design → Implementation → Validation
```

**Working Memory Structure**:
- Single problem statement
- Linear step progression
- Simple hypothesis testing
- Direct solution tracking

**Best For**: Bug fixes, small features, straightforward refactoring

### 2. Divide-and-Conquer Framework
```
Problem → Decomposition → Sub-problem Solving → Integration → Validation
```

**Working Memory Structure**:
- Problem hierarchy (main → sub-problems)
- Dependency tracking
- Parallel progress monitoring
- Integration planning

**Best For**: Large features, system refactoring, complex integrations

### 3. Scientific Investigation Framework
```
Observation → Hypothesis → Prediction → Test → Analysis → Conclusion
```

**Working Memory Structure**:
- Evidence collection workspace
- Hypothesis management
- Experimental design
- Results analysis

**Best For**: Debugging, performance issues, unknown behaviors

### 4. Design Space Exploration Framework
```
Requirements → Options → Evaluation → Selection → Implementation → Review
```

**Working Memory Structure**:
- Option matrix
- Criteria weighting
- Trade-off analysis
- Decision rationale

**Best For**: Architecture decisions, technology selection, design choices

## Cognitive Load Management Strategies

### High Cognitive Load Indicators
- Multiple competing hypotheses
- Complex dependency chains
- Many context switches
- Time pressure
- Unclear requirements

### Load Reduction Techniques

**Externalize Mental Models**:
- Write down all assumptions
- Visualize complex relationships
- Create decision trees
- Document reasoning chains

**Chunking Strategies**:
- Group related concepts
- Create meaningful abstractions
- Use consistent naming patterns
- Establish clear boundaries

**Progressive Disclosure**:
- Focus on current level of detail
- Hide non-essential complexity
- Reveal details as needed
- Maintain overview perspective

### Context Switching Optimization

**Minimal Context Switch** (< 5 minutes away):
- Keep current state in working memory
- Note return point
- Set reminder for quick return

**Medium Context Switch** (5-30 minutes away):
- Capture detailed current state
- Document next actions
- Prepare return context

**Major Context Switch** (> 30 minutes away):
- Complete current reasoning cycle
- Archive to short-term memory
- Clean cognitive workspace
- Prepare full context reload

## Real-Time Problem-Solving Support

### Decision Point Templates

**Quick Decision** (< 2 minutes):
```
**Decision**: [What needs to be decided]
**Options**: [A, B, C]
**Gut Check**: [Initial intuition]
**Quick Analysis**: [1-2 key factors]
**Decision**: [Choice made]
```

**Deliberate Decision** (2-15 minutes):
```
**Decision**: [What needs to be decided]
**Stakeholders**: [Who is affected]
**Options**: [Detailed option analysis]
**Criteria**: [Evaluation framework]
**Trade-offs**: [Key compromises]
**Timeline**: [When decision is needed]
**Decision**: [Choice made with rationale]
```

**Strategic Decision** (> 15 minutes):
```
**Decision**: [What needs to be decided]
**Context**: [Background and constraints]
**Research**: [Information gathering needed]
**Analysis**: [Detailed evaluation]
**Consultation**: [Input from others]
**Impact Assessment**: [Consequences analysis]
**Decision**: [Choice made with full rationale]
```

### Problem Escalation Triggers

**Escalate When**:
- Cognitive load becomes overwhelming
- Multiple failed solution attempts
- Time investment exceeds expected duration
- Dependencies block progress
- Requirements become unclear

**Escalation Actions**:
1. Document current state completely
2. Identify specific help needed
3. Prepare context for others
4. Consider alternative approaches
5. Set checkpoint for reassessment
